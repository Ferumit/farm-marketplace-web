# /.well-known

Файлы, которые читают не люди, а другие системы.

## assetlinks.json — Android App Links

Говорит Android: ссылки на `example.kz` можно открывать в приложениях ET и ET Partners без
вопроса «чем открыть?». Без этого файла ссылка на совместную покупку открывает браузер, даже
если приложение установлено.

Отпечатки должны совпадать с сертификатом, которым подписан **установленный** APK:

| Отпечаток | Откуда | Зачем |
|---|---|---|
| upload key | `android/app/*.jks` в репозиториях приложений | локальные release-сборки и внутреннее тестирование |
| **app signing key** | Play Console → App integrity → App signing | **то, чем Google подписывает то, что скачивают из стора** |

Состояние: у обоих приложений по два отпечатка — upload-ключ и ключ подписи Play. Этого
достаточно и для сборок, установленных вручную, и для того, что скачивают из стора.

Отпечаток берётся не руками: на странице «Подписи приложений» Play Console внизу есть готовый
блок «Протокол связи цифровых объектов в формате JSON» — в нём уже стоит нужный ключ. Отпечатков
в массиве `sha256_cert_fingerprints` может быть несколько, и это нормально: старый ключ подписи и
upload-ключ оставляют, чтобы не сломать уже установленные сборки.

Проверить после выкладки:

    curl -s https://example.kz/.well-known/assetlinks.json | head
    # и глазами Google:
    # https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://example.kz&relation=delegate_permission/common.handle_all_urls

nginx отдаёт этот каталог специально: правило `location ~ /\.(?!well-known/)` закрывает все
точечные каталоги, кроме этого (иначе certbot не обновит сертификат). Content-Type `application/json`
Android требует обязательно — nginx проставляет его сам по расширению.
